# SlideHouse

A local-first editor for Reveal.js slide decks, with one feature that most
presentation tools make hard: **copy an element and paste it into another deck**.

SlideHouse edits the `slides_*/index.html` files that Slides.com exports (and
plain Reveal.js decks that use the same `.sl-block` markup) in place. No
account, no cloud, no separate project format.

The name is a house of slides, and a nod to the surname Casas.

## Requirements

- Python 3.10 or newer. The server uses the standard library only.
- Optional: Chrome or Chromium for **Export PDF**.

## Install

With pipx (recommended, keeps a global command):

```bash
pipx install git+https://github.com/santiagocasas/slidehouse
```

With pip:

```bash
python -m pip install git+https://github.com/santiagocasas/slidehouse
```

From a checkout, for development:

```bash
git clone git@github.com:santiagocasas/slidehouse.git
cd slidehouse
python -m pip install -e .
```

## Run

```bash
slidehouse --decks-dir ~/pCloudDrive/CasasProjects/SlidesCom
```

Then open <http://127.0.0.1:8765>.

- `--decks-dir` is the folder that contains your `slides_*/index.html` decks.
  Without it, SlideHouse uses `$SLIDEHOUSE_DECKS`, then the current folder if it
  already contains decks, then `./decks`.
- `--port 9000` changes the port.
- `slidehouse --version` prints the version.

Try it immediately with the bundled example:

```bash
slidehouse --decks-dir examples
```

The server binds only to `127.0.0.1` and refuses writes from foreign origins.

## The workflow this release is built around

### Copy an element to another slide

1. Click a block in the preview, or an entry in **Elements**.
2. Press **Ctrl/Cmd+C**, or click **Copy element**.
3. Change slide (← →, the ‹ › buttons, or the outline) and press **Ctrl/Cmd+V**,
   or click **Paste element**.

Text, shapes, images and formulas are supported. One element at a time. The
paste is a single undo step.

### Copy an element to another deck

1. Copy the element in one tab.
2. Open a second tab with another deck:
   `http://127.0.0.1:8765/?deck=slides_other`.
3. Paste there.

Both tabs must use the same SlideHouse server and the same URL host
(`127.0.0.1` or `localhost`, not one of each). Local images and fonts are copied
into the destination deck under `slidehouse-assets/`, so the pasted element keeps
working after the source deck is deleted.

### Use a deck as the basis for a new one

**Copy deck…** duplicates the saved deck into `slides_<new-name>/` (HTML, styles,
runtime and assets) and opens the copy. Save the current deck first.

### Name a slide

The outline labels each slide with its own text. To use a different name,
double-click the slide in the outline, or edit **Slide name** in the inspector.
Leave the field empty to go back to the automatic name. The name is stored as
`data-title` on the slide, so it survives save and reload and does not change
what the audience sees.

## What carries over

- Text content, inline formatting and editable LaTeX source.
- Position, size and stacking.
- A captured appearance: fonts, colours, borders, backgrounds, spacing.
- Local images, SVG assets and web fonts, copied into the destination deck.
- A uniform scale when the destination canvas has a different size.

External `http(s)` images stay external by design. The source deck's entire
stylesheet is never copied, because that would restyle the destination.

## Shortcuts

| Key | Action |
| --- | --- |
| `Ctrl/Cmd+C` / `V` | Copy / paste the selected element (outside text fields and text selections) |
| `Ctrl/Cmd+S` | Save |
| `Ctrl/Cmd+Z` | Undo |
| `Ctrl/Cmd+Shift+Z` or `Ctrl+Y` | Redo |
| `←` `→` `↑` `↓` | Previous / next slide (when focus is not in a field) |

## Saving and safety

- **Save** writes `index.html` atomically.
- Every save first copies the previous file to
  `.slidehouse-backups/<deck>/<timestamp>.html`.
- If the file changed on disk since it was loaded (edited by an agent, by the
  sync client or by hand), saving is refused and nothing is overwritten.
- Uploaded images go to `<deck>/slidehouse-assets/` with content-hashed names.
- Unsaved changes trigger a warning before closing the tab.
- If a deck is generated by a build script, do not regenerate it while you have
  unsaved SlideHouse edits: the script replaces the file. SlideHouse still keeps
  the previous version in `.slidehouse-backups/`.

## Limits in 0.1

- One element at a time; no group/multi-selection.
- Cross-tab copy requires one shared local server, not different machines.
- Only `.sl-block` elements produced by Slides.com-style decks are understood.
- A deck needs a compatible math runtime for pasted formulas to render.
- Old transfer ids expire when the server restarts; copy the element again.
- Copying an element does not garbage-collect assets after an undo.
- PDF export needs Chrome/Chromium and a saved deck.

## Development

```bash
python -m unittest discover -s tests -v      # backend + API tests
python tests/browser/test_clipboard.py       # end-to-end, needs playwright + Chrome
```

The browser test skips cleanly when Playwright is not installed. Install it with:

```bash
python -m pip install playwright
```
